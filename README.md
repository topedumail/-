# בוט מענה אישי לארגון — הצעה והדגמה (POC)

> מסמך זה מציג **פרוטוטייפ עובד** של בוט שעונה לעובדי הארגון על סמך מסמכי הארגון. המסמך מסביר את הרעיון, איך מריצים את ההדגמה, מה היא מדגימה, ומה נדרש כדי להפוך אותה למערכת אמיתית.

---

## על קצה המזלג

הבוט עובד בשיטה שנקראת **RAG** (Retrieval-Augmented Generation):

1. **שולפים מידע** מתוך המסמכים של הארגון.
2. **שולחים אותו** למודל שפה גדול (כאן: OpenAI) ביחד עם השאלה.
3. המודל מנסח תשובה **על סמך המסמכים האלה בלבד**, ומציין את המקור.

החוזק של השיטה: הבוט לא "ממציא". הוא עונה אך ורק על סמך מה שנכתב במסמכים שאתם מספקים לו. אם אין תשובה במאגר — הוא אומר שאין לו מידע.

## איך להריץ את ההדגמה (5 דקות)

### דרישות מקדימות
- Python 3.10+ מותקן (כאן: 3.14)
- מפתח OpenAI API ([להשגה כאן](https://platform.openai.com/api-keys))

### שלבים
1. **הגדרת מפתח** — צור קובץ `.env` בתיקייה הראשית:
   ```
   OPENAI_API_KEY=sk-...
   ```
   (אפשר להעתיק את `.env.example` ולשנות בו את המפתח.)

2. **העלאת מסמכים** — שים קבצים בתיקייה:
   ```
   backend/data/knowledge/
   ```
   פורמטים נתמכים: `.txt`, `.md`, `.docx`, `.pdf`.
   *(תיקיה ריקה לחלוטין? הבוט יעלה אבל יגיד שאין לו מידע. שים שם לפחות קובץ אחד.)*

3. **הרצה** — מ-PowerShell:
   ```powershell
   .\run.ps1
   ```
   הסקריפט יתקין את כל מה שצריך בפעם הראשונה ויפעיל את השרת.

4. **שימוש** — פתח/י בדפדפן: <http://localhost:8000>

### הוספת מסמכים אחרי שהבוט רץ
- שים קבצים חדשים בתיקייה `backend/data/knowledge/`.
- בממשק לחץ/י על **"רענן מאגר"**.
- שינויים בקבצים קיימים יזוהו אוטומטית (לפי תוכן הקובץ).

## מה ההדגמה כן מראה

✅ **תשובות מבוססות מקור** — כל תשובה כוללת ציטוטים מתוך המסמכים.
✅ **סינון hallucinations** — אם המידע לא במסמכים, הבוט אומר זאת ולא ממציא.
✅ **קלות עדכון** — להוסיף מסמך = להעתיק קובץ לתיקייה ולרענן.
✅ **תמיכה בעברית** — embeddings ו-LLM מודרניים תומכים בעברית מצוין.
✅ **Caching** — embeddings נשמרים בדיסק, אז ריצה חוזרת מהירה וזולה.
✅ **שקיפות** — בכל תשובה אפשר לפתוח את "המקורות שאוחזרו" ולראות בדיוק מה הבוט קרא.

## מה ההדגמה לא מראה (ולמה זה חשוב לדעת)

⚠️ **אין מערכת משתמשים** — כולם רואים את כל המאגר. במערכת אמיתית כל משתמש יזדהה ויראה רק מה שמותר לו.
⚠️ **אין הרשאות לפי מחלקה** — תכננו את זה לפרויקט המלא, אבל ב-POC הוצא מהמשוואה.
⚠️ **OpenAI הציבורי** — המידע *עובר* ל-OpenAI. **במערכת אמיתית במוסד טיפולי חייבים** לעבור ל-Azure OpenAI עם DPA, או לפתרון מקומי. אסור לטעון מסמכים רגישים אמיתיים ל-POC הזה.
⚠️ **אין שמירת היסטוריית שיחה** — כל שאלה עומדת לעצמה.
⚠️ **חיפוש בסיסי** — embedding-only, ללא BM25/re-ranking. במערכת מלאה איכות החיפוש משתפרת משמעותית.
⚠️ **אין observability** — אין מעקב מסודר אחרי תשובות שגויות, אין dashboard, אין feedback.
⚠️ **אין guardrails** — אין סינון של תכנים רגישים, אין זיהוי של ניסיון להוציא מידע אישי.
⚠️ **PDF סרוק לא נתמך** — רק PDF שיש בו טקסט. סרוקים דורשים OCR.

## מה זה אומר על הפרויקט האמיתי

### שלבים בין POC למערכת ייצור

| שלב | מה כולל | זמן משוער |
|-----|---------|-----------|
| **0. החלטות יסוד** | חוזה עם ספק LLM (Azure DPA), בחירת ענן, אישור מהמנהל המוסדי | 2–4 שבועות |
| **1. POC זה** | מה שמוצג כאן + עוד מסמכים אמיתיים (אנונימיים) | 1–2 שבועות |
| **2. הרשאות ואבטחה** | זיהוי משתמשים, סינון לפי מחלקה/תפקיד, audit log | 2–3 שבועות |
| **3. שיפור איכות** | hybrid search, re-ranking, system prompts מותאמים לתפקיד, guardrails | 2–3 שבועות |
| **4. תשתית** | מעבר ל-Azure OpenAI, vector DB אמיתי (pgvector), Redis cache | 2 שבועות |
| **5. observability** | Langfuse, feedback מהמשתמשים, דאשבורד אדמין | 1–2 שבועות |
| **6. Production hardening** | rate limits, backups, מוניטורינג, תיעוד, בדיקות עומס | 2 שבועות |

**סה"כ**: כ-12–18 שבועות לפרויקט מלא. POC עובד עם מסמכים אמיתיים אנונימיים — אפשר לקבל תוך שבוע.

### עלויות משוערות (לפי 100 משתמשים, ~50 שאלות ביום)

| רכיב | חודשי משוער |
|------|--------------|
| OpenAI / Azure OpenAI (gpt-4o-mini + embeddings) | $30–$80 |
| שרת אפליקציה (cloud VPS) | $20–$50 |
| Vector DB (pgvector על אותו שרת) | כלול |
| Cache (Redis, self-hosted) | כלול |
| Observability (Langfuse self-hosted) | כלול |
| **סה"כ תפעולי** | **~$50–$130/חודש** |

לא כולל פיתוח ראשוני.

### חשוב במיוחד למוסד טיפולי/חינוכי

1. **הסכם DPA** — לפני שמעלים מסמך אחד אמיתי, חייב להיות הסכם עם ספק ה-LLM שמבטיח שהמידע לא משמש לאימון, נמחק, ויש לו location מוגדר.
2. **תקנות הגנת הפרטיות (ישראל)** — לבדוק מול היועץ המשפטי של הארגון אם המאגר הוא "מאגר מידע" שדורש רישום, ואיזה רמת אבטחה נדרשת.
3. **אסור לחשוף ילדים/מטופלים בודדים** — המאגר צריך להיות **אנונימי**, גם פנימית. אם יש דוגמאות מקרה, שמות וזיהויים מוסרים.
4. **אדם בלולאה** — תשובות לשאלות רגישות (אבחנות, החלטות טיפוליות) צריכות לכלול אזהרה "מומלץ לאמת עם גורם מקצועי".

```

├── README.md                       ← המסמך הזה
├── requirements.txt                ← תלויות Python
├── run.ps1                         ← סקריפט הפעלה (Windows)
├── .env.example                    ← תבנית להגדרת מפתחות
├── .gitignore
├── backend/
│   ├── main.py                     ← FastAPI app (endpoints)
│   ├── rag.py                      ← אינדקס וקטורי + חיפוש
│   ├── loaders.py                  ← קריאת txt/md/docx/pdf + chunking
│   ├── llm.py                      ← קריאה ל-OpenAI עם system prompt
│   └── data/
│       ├── knowledge/              ← *** כאן שמים את המסמכים ***
│       └── .embed_cache.pkl        ← cache (נוצר אוטומטית)
└── frontend/

```
